# SafeKey

> **WIP:** приложение не доделано и сейчас не работает. Это промежуточный merge, чтобы зафиксировать текущее состояние.

Кроссплатформенный offline-first менеджер паролей. **Полностью бесплатная схема**: статическое PWA на GitHub Pages + зашифрованная синхронизация через **Яндекс Диск или Google Drive** (на выбор). Собственного сервера нет вообще — нечего хостить, нечем платить. Из того же кода собираются нативные приложения: **.exe для Windows, .dmg для macOS, .AppImage/.deb для Linux и .apk для Android** (Tauri 2, сборка на GitHub Actions — бесплатно).

## Что реализовано

- создание сейфа и разблокировка мастер-паролем;
- AES-256-GCM с уникальным IV при каждом сохранении;
- ключ из мастер-пароля через PBKDF2-SHA-256 (600 000 итераций, случайная 128-битная соль);
- создание, редактирование, удаление, поиск, избранное и генератор стойких паролей;
- локальная проверка слабых и повторяющихся паролей;
- зашифрованный экспорт/импорт `.skvault`;
- синхронизация на выбор: **Яндекс Диск** (папка приложения, implicit OAuth) или **Google Drive** (скрытая папка appDataFolder, OAuth code + PKCE, тихое обновление токена) — **zero-knowledge**, в облако уходит только шифротекст;
- подключение устройства = вход в тот же облачный аккаунт + мастер-пароль (никаких кодов и сервера pairing);
- контроль версий по md5: автосинхронизация после каждого изменения, конфликт обеих сторон решает пользователь;
- адаптивный интерфейс, PWA manifest + service worker — установка на ПК и телефон, работа офлайн;
- нативные сборки: `deploy/github-actions/release-desktop.yml` (.exe/.dmg/.deb/.AppImage) и `release-android.yml` (.apk);
- демонстрационный сценарий (демо-пароль хранится отдельно только для демо-сейфа).

## Архитектура

```
Браузер / Tauri (нативные сборки) — один и тот же код
 ├─ шифрование/расшифрование — Web Crypto, только на устройстве
 ├─ локальная копия — localStorage (AES-GCM контейнер)
 └─ синхронизация — REST API облака прямо из приложения
      ├─ Яндекс Диск: Приложения/SafeKey/safekey.vault (implicit OAuth)
      └─ Google Drive: скрытая appDataFolder/safekey.vault (code + PKCE)
      в обоих случаях — только шифротекст
```

- Express-сервер, Docker и Render больше не нужны и удалены.
- Сборка `vite build` даёт полностью статический `dist/` с относительными путями — работает в подкаталоге GitHub Pages (`https://<user>.github.io/password/`) и на любом другом статическом хостинге.
- CSP задаётся метатегом в `index.html`: скрипты только со своейorigin, запросы — только к API Диска.

## Развёртывание на GitHub Pages

Готовые workflow лежат в `deploy/github-actions/` (у токена бота нет права писать в `.github/workflows/`, поэтому их нужно включить один раз владельцу репозитория):

1. Скопируйте workflow в рабочую директорию GitHub Actions и закоммитьте:

   ```bash
   mkdir -p .github/workflows && cp deploy/github-actions/*.yml .github/workflows/
   git add .github/workflows && git commit -m "ci: включить GitHub Actions"
   ```

2. **Settings → Pages → Build and deployment → Source: GitHub Actions** (один раз).
3. Пушьте в `main` — `deploy-pages.yml` соберёт и опубликует сайт.
4. Готово: `https://<user>.github.io/password/`.

Проверки типов, smoke-тест синхронизации и сборку гоняет `ci.yml` на каждый PR. Собранный сайт полностью статический, поэтому его можно выложить и на любой другой хостинг (`npm run build` → `dist/`) — достаточно указать правильный Redirect URI в OAuth-приложении.

## Нативные приложения: .exe, .dmg, .AppImage и .apk

Тот же веб-код упаковывается в нативные приложения через [Tauri 2](https://v2.tauri.app) (конфигурация — `src-tauri/`). Сборка идёт **бесплатно на GitHub Actions** — локально ничего компилировать не нужно:

1. Скопируйте workflow из `deploy/github-actions/` в `.github/workflows/` (как для Pages).
2. Запушьте тег: `git tag v1.2.0 && git push origin v1.2.0` (или запустите workflow вручную — *Run workflow*).
3. В итоговом запуске появится **Artifacts**: установщик `.exe` (Windows), `.dmg` (macOS), `.deb`/`.AppImage` (Linux), подписанный `.apk` (Android, arm64).

Что важно знать:

- **Windows**: установщик NSIS без подписи кода — SmartScreen предупредит («Подробнее» → «Выполнить в любом случае»). Подпись сертификата — отдельная платная история.
- **macOS**: ad-hoc подпись, первый запуск через ПКМ → «Открыть». Сборка идёт на macos-раннере — Mac для этого не нужен.
- **Android**: APK подписывается самоподписанным ключом, который генерируется прямо в CI — устанавливается вручную («неизвестные источники»). Для Google Play нужен аккаунт разработчика ($25) и постоянный keystore в Secrets.
- Приложение при открытии не требует сервера: интерфейс грузится из bundled-файлов, а синхронизация работает так же, как в вебе — Яндекс Диск или Google Drive.

Локальная сборка на своём компьютере (нужен Rust): `npm i -D @tauri-apps/cli && npx tauri icon public/icon-512.png && npx tauri dev`.

## Настройка синхронизации

Синхронизация идёт напрямую из браузера, поэтому нужен OAuth ClientID выбранного облака — это бесплатно. ClientID задаётся в `public/app-config.js` (для своего форка) или прямо в приложении («Синхронизация» → «Подключить облако»). Приложения запрашивают минимальные права — только свою папку, остальные файлы на Диске/Drive им не видны.

### Вариант 1: Яндекс Диск

1. Откройте [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new).
2. Название: `SafeKey`. Платформы: **Веб-сервисы**.
3. **Redirect URI**: точный адрес приложения, например `https://<user>.github.io/password/` (с завершающим `/`). Для отладки добавьте `http://localhost:5173/`.
4. Доступы: **Яндекс Диск REST API → Доступ к папке приложения** (`cloud_api:disk.app_folder`).
5. Скопируйте **ClientID** в `public/app-config.js` → `YANDEX_CLIENT_ID` или введите в приложении.

Файл появится в Диске: `Приложения/SafeKey/safekey.vault` — обычный зашифрованный контейнер. Токен долгоживущий, хранится в localStorage устройства и отзывается кнопкой «Отключиться» (`oauth.yandex.ru/revoke_token`).

### Вариант 2: Google Drive

1. Откройте [console.cloud.google.com](https://console.cloud.google.com/) → создайте проект (например, `SafeKey`).
2. **APIs & Services → Library** → включите **Google Drive API**.
3. **APIs & Services → OAuth consent screen**: тип External, режим Testing, добавьте свой аккаунт в Test users.
4. **Credentials → Create credentials → OAuth client ID** → тип **Web application**:
   - **Authorized JavaScript origins**: `https://<user>.github.io` (только источник, без пути) и `http://localhost:5173`;
   - **Authorized redirect URIs**: `https://<user>.github.io/password/` и `http://localhost:5173/`.
5. Скопируйте **ClientID** (`...apps.googleusercontent.com`) и **Client Secret** (на той же странице клиента, рядом с ClientID). Оба значения введите в приложении в карточке Google Drive («Синхронизация» → «Подключить облако» или экран «Облачный сейф»). ClientID можно также задать в `public/app-config.js` (`GOOGLE_CLIENT_ID`); **Client Secret в код/репозиторий класть нельзя** — он хранится только в localStorage вашего браузера, в открытом коде приложения его нет.

Особенности Google: OAuth authorization code + PKCE, и Google для клиента «Web application» при обмене кода на токен дополнительно требует **client_secret** (иначе токен-эндпоинт отвечает 400). Секрет отправляется только в запросе обмена `code → token` на `oauth2.googleapis.com` из вашего браузера. Токен живёт ~1 час и **обновляется тихо** в скрытом iframe (`prompt=none`), пока в браузере активна сессия Google — пароль заново вводить не нужно. Файл лежит в скрытой папке приложения (**appDataFolder**): в интерфейсе Drive он не виден, приложение видит только эту папку. Все запросы — `www.googleapis.com`, CORS поддерживается, прокси не нужны.

## Как добавить устройство

1. Откройте тот же адрес (или установите PWA / нативное приложение) на втором устройстве.
2. «Облачный сейф» → выберите то же облако (Яндекс или Google) и войдите в тот же аккаунт.
3. Введите мастер-пароль — сейф скачается и расшифруется локально.

## Модель безопасности

Открытые данные существуют только в памяти вкладки после разблокировки. В `localStorage` хранится JSON-контейнер с солью, IV, параметрами KDF и шифротекстом (плюс OAuth-токен Диска — при желании устройство отключается одной кнопкой с отзывом токена). Мастер-пароль нигде не записывается. AES-GCM одновременно шифрует данные и проверяет целостность: чужой или повреждённый файл просто не расшифруется.

Конфликт версий: перед каждой автозаписью SafeKey сравнивает md5 файла на Диске с последней синхронизированной версией (optimistic concurrency). Если изменились обе стороны — приложение спросит, какую оставить; ничего не теряется молча.

Важно: браузерное приложение не может защитить данные на уже заражённом устройстве (кейлоггер, вредоносное расширение, скомпрометированная ОС). Потерянный мастер-пароль невозможно восстановить — храните резервную копию `.skvault` в настройках. Для реального продукта перед публикацией нужен независимый криптографический аудит.
