# SafeKey

Кроссплатформенный offline-first менеджер паролей. Работает как адаптивное веб-приложение и устанавливается на ПК/телефон как PWA.

## Что реализовано

- создание сейфа и разблокировка мастер-паролем;
- AES-256-GCM с уникальным IV при каждом сохранении;
- ключ из мастер-пароля через PBKDF2-SHA-256 (600 000 итераций, случайная 128-битная соль);
- создание, редактирование, удаление, поиск, избранное и генератор стойких паролей;
- локальная проверка слабых и повторяющихся паролей;
- зашифрованный экспорт/импорт `.skvault` для безопасного переноса;
- адаптивный интерфейс для компьютера и телефона;
- PWA manifest + service worker для установки и работы офлайн;
- демонстрационный сценарий (демо-пароль хранится отдельно только для демо-сейфа).

## Модель безопасности

Открытые данные существуют только в памяти вкладки после разблокировки. В `localStorage` сохраняется JSON-контейнер с солью, IV, параметрами KDF и шифротекстом. Мастер-пароль не записывается на диск. AES-GCM одновременно шифрует данные и проверяет их целостность.

Важно: браузерное приложение не может защитить данные на уже заражённом устройстве (кейлоггер, вредоносное расширение, скомпрометированная ОС). Потерянный мастер-пароль невозможно восстановить. Для реального продукта перед публикацией нужны независимый криптографический аудит, CSP, защита цепочки поставок и сервер синхронизации.

## Облачная синхронизация

В репозитории есть рабочий Express backend (`server.mjs`). Клиент обращается к нему только по same-origin `/api`:

1. Сейф шифруется на клиенте до отправки.
2. Сервер хранит только AES-GCM контейнер, номер версии и SHA-256 хеш токена доступа.
3. Изменения используют optimistic concurrency: устаревшая версия получает HTTP 409 и не перезаписывает новую.
4. Подключение устройства выполняется одноразовым шестизначным кодом со сроком жизни 10 минут.
5. Полученный шифротекст открывается локально исходным мастер-паролем.
6. Серверная база записывается атомарно в `data/cloud.json` с правами `0600`; каталог исключён из Git.

Для локальной разработки `npm run dev` одновременно запускает API на 8787 и Vite на 5173 с proxy. В production команда `npm start` раздаёт собранный `dist` и API одним Express-процессом.

## Одна сборка для ПК и телефона

SafeKey — устанавливаемое PWA. Отдельные `.exe` и `.apk` не нужны: один HTTPS-адрес открывается на Windows, macOS, Linux, Android и iOS, а интерфейс адаптируется к экрану.

### Самостоятельный запуск через Docker

```bash
docker compose up -d --build
```

Приложение будет доступно на `http://localhost:8787`. Чтобы открыть его с телефона в той же Wi-Fi сети, используйте `http://IP-КОМПЬЮТЕРА:8787`. Для установки PWA и безопасной работы вне локальной сети нужен домен с HTTPS — не публикуйте порт напрямую в интернет.

### Облачное развёртывание

В корне есть `render.yaml` для Render Blueprint и production `Dockerfile`:

1. После слияния PR откройте [Render Blueprints](https://dashboard.render.com/blueprints).
2. Подключите репозиторий `Gamegui/password`.
3. Render прочитает `render.yaml`, соберёт контейнер и подключит постоянный диск `/app/data`.
4. Откройте выданный HTTPS-адрес на всех устройствах.

После добавления шаблона `deploy/github-actions/docker.yml` в `.github/workflows/` workflow публикует multi-platform образ `linux/amd64` + `linux/arm64` в GitHub Container Registry.

### Установка приложения

- **Chrome/Edge на ПК и Android:** откройте HTTPS-сайт → кнопка установки в адресной строке или меню → «Установить SafeKey».
- **iPhone/iPad:** Safari → «Поделиться» → «На экран Домой».
- **macOS Safari:** «Файл» → «Добавить в Dock».

Для публичного production с большим количеством пользователей замените JSON-хранилище на транзакционную БД, настройте резервные копии persistent volume и поставьте дополнительный rate limiting/WAF на reverse proxy. Всегда используйте HTTPS.
